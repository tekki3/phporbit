AI agents

Fluent text generation with OpenAI, Anthropic and compatible local providers, including real HTTP streaming.

PhpOrbit\Ai\Agent provides a fluent, immutable builder for text generation. OpenAI, Anthropic and OpenAI-compatible services share one interface. Each call owns its HTTP connection; prompts, credentials and conversation state are never cached globally. This is a text-generation API, not an autonomous tool-running agent.

Use a non-sensitive prompt and do not commit your key. If the call fails, follow the error checklist; do not share raw credentials or provider responses in a bug report.

For Claude, switch the provider, key and model together. To print chunks instead of waiting for one answer, use the streaming variant. Framework configuration methods are typed; a global env() helper does not exist.

Configuration

Enable ext-curl and configure a provider key in your real environment or .env. Configuration is read at boot through Environment, not a global env() helper. Keep keys on the server. The framework does not contact a provider automatically.

A live call can incur costs and sends your prompt to the configured provider. Do not send secrets or personal data without an appropriate data-handling policy and consent. Only synthetic, local provider responses are used by the framework tests; live model access and billing have not been verified here.

One answer

The model is explicit, not a framework default. Choose a model available to your provider account. OpenAI uses /v1/chat/completions, with max_completion_tokens; this supports the example's familiar chat interface, not every capability of OpenAI's Responses API. Parameter/model compatibility is the provider's responsibility.

withStreaming() returns a StreamingAgent whose send() returns a Generator<int, string>. It does not issue a request until iteration starts. Chunks contain text only, not raw SSE/JSON or provider metadata. Chunks are arbitrary text fragments, not complete words or lines. Configuration methods belong before withStreaming(). You can also use $agent->stream() directly.

If iteration is abandoned, release the generator (for example unset($stream)) so its finally closes the upstream connection promptly. There is no automatic retry: retrying a partial generation could repeat text and incur another charge.

Before exposing it, wire it into your application's guarded routes and apply rate limits and a budget policy. Do not use a public generated API as an unrestricted AI proxy.

This is an incremental text/plain; charset=utf-8 response. It sets Cache-Control: no-store and X-Accel-Buffering: no. The own server uses HTTP/1.1 chunk framing; FPM/Apache/FrankenPHP flush PHP's output layer. Browser clients can consume a fetch response's readable body. This is not browser EventSource framing; use a custom Response::stream() producer if you need SSE.

The first text fragment is obtained before committing response headers. An initial failure becomes an ordinary 500; failures after output starts are logged by exception class and terminate the stream. A partial response cannot retroactively become a JSON error or change its HTTP status. Never treat an incomplete stream as a completed answer.

The kernel keeps the request scope and temporary uploads alive through emission and closes the scope in finally, including when a client disconnects or an upstream fails. Complete authentication, cookies and session changes in the handler before returning the response. Session writes during lazy generation throw rather than being silently lost. Do not open a transaction across a long AI call; TransactionGuard also cleans transactions opened during stream iteration.

Configure your reverse proxy/CDN not to buffer this route, disable compression/output handlers that buffer, and allow suitable request timeouts. The web emitter supports at most one flushable PHP output buffer; nested/nonflushable buffers fail explicitly instead of silently buffering a stream. PHP/web-server configuration can still buffer despite application flush calls. Orbit's development server is sequential: one long generation occupies it until completion. Production streaming also occupies a worker. Authenticate and rate-limit any publicly accessible AI endpoint and enforce your own budget policy.

Request-logging middleware measures handler/pipeline time, not the full duration of stream consumption. The kernel logs later emission failures separately. Stream responses and their iterators are single-use; an emitter must consume synchronously, not save them for use after the scope closes.

Compatible and local providers

OpenAICompatible uses the OpenAI chat/SSE shape and max_tokens. Its default endpoint is the loopback URL above. endpoint() takes the complete request URL, not a base URL. Remote endpoints require HTTPS with peer/host verification; plain HTTP is permitted only for literal loopback hosts. Redirects are disabled, and URLs must not contain credentials, query strings or fragments. Endpoint configuration is operator-controlled: never accept an arbitrary endpoint from user input.

Errors, limits and test doubles

  • Missing extension: check php -m for curl and enable it in the configuration reported by php --ini.
  • Missing key or model: verify the names in .env match the chosen provider. Real environment variables override the file. Do not print configuration values while diagnosing a failure.
  • Provider HTTP error: check account access, the exact model identifier, quota and billing in the provider's dashboard. No automatic fallback or retry is performed.
  • Delayed web output: return response(), not an echoed send() result, and check the buffering and timeout requirements.

Catch AiFailed for transport, HTTP, provider-response, truncation or event-size failures. Exception messages never contain provider response bodies, keys or prompts. Missing/invalid builder inputs throw InvalidArgumentException. A key is validated without silently falling back to another provider or environment variable. Agent/request/credential debug output is redacted and serialization is refused.

Default limits: 1 MiB for prompt plus system text, 16 MiB total provider response, 1 MiB per pending transport buffer/SSE event, 1024 output tokens and a 120-second timeout (configurable from 1 to 600 seconds). Each provider request uses a fresh connection. No retries, background jobs or provider calls at boot are added.

Agent::using() accepts a Provider class or instance. The interface supplies the endpoint, request body/headers and text/SSE decoding. withTransport(Transport $transport) supports isolated tests; a transport returns raw byte fragments and must enforce HTTP status, media type, size and timeout rules. Framework providers and builders are stateless/immutable. Custom providers/transports must not retain per-user request data when registered as singletons.
