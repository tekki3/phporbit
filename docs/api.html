APIs

JWT and personal Bearer tokens, versioned routes, shared rate limits and local Swagger UI.

First-class APIs use the same request pipeline on workers and per-request SAPIs. The demo and make:auth include JSON login, scoped profile access, token revocation, browser-based personal-token management and interactive Swagger UI. Browser sessions never authenticate Bearer routes.

Start here

For a new endpoint, use the CLI. It writes the JSON controller and an editable declaration, then loads that declaration automatically at boot. No route registration needs to be pasted.

make:api Products creates app/src/Controllers/Api/V1/ProductsController.php and app/api/v1/products.php. Edit the controller to return your data and the declaration to describe the operation in OpenAPI. The initial response is {"message":"It works"}. Names use StudlyCase and may be nested, such as Admin/Report. Supported methods are GET, POST, PUT, PATCH and DELETE; versions range from 1 to 999. Existing files are never overwritten.

Bearer protection is the default. In a blank project, run php orbit make:auth once to install account/token authentication, or supply your own Tokens service and dependencies. A public endpoint needs no account setup. All generated endpoints default to sixty requests per minute, per user and operation (a shared anonymous bucket for public endpoints). The command installs the API migration and local Swagger assets when needed; run migrations before making requests. Adding authentication later reuses the existing API schema.

Blueprint::loadRoutes() automatically discovers adjacent api/vN/*.php declarations when loading app/routes.php. Each file returns a closure taking VersionedRoutes. Files are loaded once at boot, not during requests. The CLI route list, admin route list and the demo/generated-auth OpenAPI document include these endpoints too. Projects using a custom routing bootstrap can explicitly call RouteFiles::register($routes, $root . '/app/api'). Custom documentation handlers can merge declarations using RouteFiles::document($directory, $existingDocument).

The demo uses the existing seeded account. Generated authentication uses your verified account. Visit /api/docs for Swagger UI, /api/openapi.json for the OpenAPI 3.0.3 document, and /account/tokens while signed in to create or revoke personal tokens. Run migrations before calling token or rate-limit endpoints. Restart workers after application or configuration changes.

Omit code only when MFA is not enabled. The login endpoint returns access_token, token_type: "Bearer" and expires_in: 900. Incorrect credentials and missing, invalid or replayed MFA codes share a generic 401. API login creates no browser login; reset/magic/OIDC browser flows are not silently exchanged for API tokens.

Tokens and revocation

KindLifetimeUse
JWT access token15 minutes by default, at most one hourShort-lived API sessions issued after password and optional MFA.
Personal Bearer token30 days by default, at most 90 daysNamed scripts and integrations; random 256-bit secret, shown once.

Both kinds have a SHA-256 token fingerprint in api_tokens; no usable token is stored. JWTs are deliberately not stateless: every request checks expiry, the current user provider, the token record, password hash and security version. Deleting a user, blocking it through its provider, resetting its password or revoking account security invalidates tokens. A token can also be individually revoked immediately. Revocation does not log the browser out or invalidate other tokens.

JWT signing is fixed to HS256 using a purpose-derived key from APP_KEY, distinct from encryption and other signing keys. Issuer, audience, issued-at, expiry, subject, token ID and signature are verified. JWT payloads are readable, not encrypted. Signing-key rotation invalidates existing JWTs: previous application keys are not accepted for JWT verification. Personal tokens are independent of that signing key but remain bound to account security.

Use HTTPS in production and protect APP_KEY. Never put tokens in query strings, cookies, logs, emails or public caches. A compromised token has its scopes until expiry or revocation; MFA is checked at issuance, not prompted on every Bearer request. The demo grants only profile:read. There is no wildcard scope, implicit administrator access, refresh token or OAuth2 authorization server.

Personal-token management

/account/tokens requires a browser login. Creating or revoking tokens additionally requires CSRF protection, the current password and an unused MFA/recovery code when enrolled. The full token appears only in the creation response, under Cache-Control: no-store; it is never flashed into a session. Store it securely before leaving the page. Unexpired-token metadata is listed, capped at 100 entries; records invalidated by account security changes can remain listed until expiry or individual revocation. Expired records are reclaimed during token issuance. Revoke unused records before creating more.

Reusable framework services

Add a migration returning new PhpOrbit\Api\ApiMigration(). It creates token, rate-window and rate-lock tables; down() is reversible. Authentication also needs the existing SecurityMigration schema and your UserProvider. The generated auth migration already includes both; do not install them twice.

Tokens is a low-level issuance API, not an authorization decision. Never accept arbitrary client-provided scopes or user identifiers. Reauthenticate before creating tokens. JWT login captures the security version before verifying MFA and supplies it to jwt(..., securityVersion: $version), so a concurrent MFA/security change cannot upgrade an earlier primary-factor check.

Versioned routes and OpenAPI

This registers /api/v1/profile, its name, a Bearer guard, a rate limit and its OpenAPI operation from one declaration. A separate instance with version: 2 registers /api/v2/...; versions coexist explicitly. Unknown versions are not redirected to the latest. Route parameters such as {id:\d+} become OpenAPI {id} path parameters. Declare request/response schemas and additional parameters in the operation array; descriptions are not runtime validators. Use JsonBody or your own typed validation.

Bearer protection is on by default. authenticated: false deliberately opts an operation out, as the login endpoint does. Every versioned operation is CSRF-exempt because it must not rely on browser-cookie authority. Do not mount browser state changes in this collection. Use RequireBearer directly for non-versioned routes if needed; it publishes a request-local Principal containing the user, token ID and scopes. Missing or invalid tokens return 401 with WWW-Authenticate; insufficient scopes return 403.

Rate limiting

The shared database enforces a fixed window beginning on the first attempt. The lock row is written before reading counters, so simultaneous workers cannot pass a stale check. The demo allows 60 requests per minute, per authenticated user and operation, shared across that user's tokens. Public login has a shared ceiling of 30 per minute plus five attempts per normalized email over fifteen minutes, including successful attempts.

Anonymous limits are deliberately global: no untrusted forwarding header is treated as an identity. For public production APIs add trusted proxy/WAF limits, especially before invalid-token requests, and configure appropriate application limits. Account-wide login limits can be used to temporarily deny a known account access, just as other account-wide abuse controls can. The portable lock serializes short counter updates: this is reliable shared limiting, not a high-throughput Redis limiter.

Versioned middleware returns X-RateLimit-Limit, X-RateLimit-Remaining and Unix-time X-RateLimit-Reset. Exhaustion returns 429 and a positive Retry-After in seconds. Key identities are hashed in storage. Expired buckets are removed on consumption. Storage errors fail explicitly rather than disabling limits. Consumption owns a database transaction; do not call it from an already-open transaction.

JSON errors and input

Register ApiResponses for the /api prefix before other response/error middleware, with a registered Logger. It preserves JSON responses and turns API errors, 404/405 responses and unexpected failures into application/problem+json with type, title and status. Unexpected exception details are logged by class, not exposed to clients, even in debug mode. Non-API pages retain their HTML behavior. Responses are marked no-store.

JsonBody::fromRequest($request) accepts a JSON object with Content-Type: application/json, including charset parameters. It rejects malformed JSON (400), bodies above its default 16 KiB bound (413) and other media types (415). string() validates strings without coercing numbers, arrays or objects (422). This parser bound does not replace SAPI/web-server request-size limits.
