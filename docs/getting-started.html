Getting started

Create a project, run it locally, and build your first page with a route, controller and template.

This guide takes you from an empty folder to a page that says Hello, Ada!. Start with a blank project and follow the numbered steps in order. You do not need a separate web server or database server.

1. Check your tools

You should be comfortable creating files, opening a terminal and writing basic PHP (variables, arrays and functions), plus a little HTML. We explain the framework-specific terms as they appear.

  • PHP 8.3 or newer, with pdo_sqlite, mbstring, fileinfo and sodium. SQLite stores your database in a file; no database server is needed for this guide.
  • Composer, PHP's package manager. It downloads phporbit and the libraries your application needs.
  • A text editor and a browser.

Open a terminal (for example, Terminal → New Terminal in VS Code) and run these commands, one line at a time:

The first two commands should print version numbers. The last lists enabled PHP extensions; look for the four listed above. If php or composer is not recognised, install it and reopen your terminal before continuing. php --ini shows which configuration file your command-line PHP uses.

How to read the commands

Type the commands into your terminal, not into a PHP file. Code blocks here omit the prompt character so you can copy them directly. Run each next command only after the previous one succeeds. We use php orbit for project commands: it works in Windows PowerShell, macOS and Linux. Other pages use ./orbit, which is the macOS/Linux shorthand for the same script. You do not need pcntl or the sockets extension for the built-in server; it uses PHP streams, with optional signal handling when pcntl is available.

Wait for the message saying phporbit is listening, then open http://127.0.0.1:8080 in your browser. You should see the starter welcome page with the heading It works. 127.0.0.1 means your own computer; 8080 is the port the server listens on.

The terminal stays busy because it is running the server. Leave it open and use a second terminal in the same project folder for other commands. To stop the server, return to its terminal and press Ctrl+C.

Restart after PHP or configuration changes

The built-in server keeps your application running between requests. After changing routes, controllers, other PHP classes or .env, stop it with Ctrl+C and run php orbit serve --debug again. Refreshing the browser alone does not reload that code. Template edits are picked up on refresh in debug mode. Debug mode shows exception details: use it locally, never on a public deployment.

What you just built

Browser requests GET /greet/Ada → router selects GreetController → controller passes Ada to the template → template becomes an HTML response → browser displays the page.

Where things go

PathWhat to put there
app/routes.phpConnections between URLs and handlers
app/src/Controllers/Your request-handling classes, under App\Controllers
app/templates/HTML templates ending in .orbit.php
app/bootstrap.phpStartup configuration: services and middleware (layers around handlers)
database/migrations/Versioned changes to database tables
public/Browser-accessible assets and the production web entrypoint; keep secrets out
storage/Generated files: sessions, compiled templates and the SQLite database
.envLocal settings and secrets; never commit it
vendor/Composer-managed dependencies; do not edit them

If something goes wrong

SymptomWhat to check
orbit is not recognisedCheck Composer's global bin directory with composer global config bin-dir --absolute, add it to PATH, and open a new terminal.
Could not open input file: orbitMove into your project folder with cd my-app. You should see orbit and composer.json there.
Missing vendor/autoload.php or Composer autoloaderRun composer install in that project folder and resolve any errors it reports.
could not find driverEnable pdo_sqlite in the PHP configuration shown by php --ini. Check php -m, then restart the server.
Port 8080 is already in useRun php orbit serve --port=9000 --debug and open http://127.0.0.1:9000 instead.
The browser cannot connectCheck that the server terminal is still running and says it is listening. Match the URL's port to the server's port.
404 or an old version of a pageCheck the exact URL and php orbit routes. Restart after PHP changes; /greet/Ada matches, but /greet does not.
500 / Internal Server ErrorUse --debug locally, retry the request and read the error and server terminal. Check imports, spelling and semicolons. Do not turn on debug on a public server.
The generator says a file existsEdit that file rather than regenerating it. --force overwrites work; only use it if you intend to replace the file.

What to learn next

  1. Routing and controllers: more URL patterns and request handlers.
  2. Templates: layouts, loops and reusable page parts.
  3. Forms: render inputs, validate submissions and keep CSRF protection enabled.
  4. Database, migrations and models: create tables and store application data.
  5. Testing: check your application with composer test and composer stan.
  6. Deployment: publish using FrankenPHP, nginx + PHP-FPM or Apache, with debug disabled. The built-in server is for local development.

Prefer a local dashboard for generators and migrations? Run php orbit ui in a second terminal and visit http://127.0.0.1:8081. It has no login: keep it bound to the default 127.0.0.1 and do not expose it publicly. See Admin UI and the CLI command reference.

Before adding services that hold state, read service lifetimes and architecture. In plain terms: a running worker serves many visitors, so never store the current visitor's data in static properties or singleton services. Use phporbit's request-scoped services and sessions instead of PHP's global session functions.
